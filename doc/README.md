# Документация OzonPilot

**OzonPilot** (`OzonPilot.exe`, в коде и репозитории — модуль `CLIForOZON`) — консольная утилита на Go для контроля остатков и расчёта поставок на склады Ozon по гибридной схеме **FBO + FBS**. Она собирает фактические остатки Ozon и собственного склада, считает спрос по истории отправлений и выдаёт Excel-отчёт: сколько и в какой кластер везти, где товар заканчивается, сколько стоит хранение.

Эта папка — техническая документация «как оно работает на самом деле». Она описывает текущий код, а не благие намерения: все формулы, лимиты и правила взяты из исходников, тестов и реального прогона.

## Что делает программа за один запуск

1. Читает конфиг и флаги.
2. (online) Проверяет ключи Ozon.
3. Загружает каталог → SKU и названия → остатки FBO по кластерам → остатки FBS → историю отправлений FBO за `-prodazhi` дней.
4. Загружает отчёт о стоимости размещения: из файла `-placement-file` или через API Ozon.
5. Считает по каждому товару и кластеру: продажи, остаток, рекомендуемую поставку, статус.
6. Сохраняет Excel-отчёт в папку `reports` рядом с исполняемым файлом и печатает путь в лог.

Консольная таблица-сводка в текущей версии отключена (код есть, вызов закомментирован) — результат живёт только в Excel.

## Быстрый старт

### Windows

```powershell
# 1. Положить OzonPilot.exe в любую папку (в неё же будут писаться reports)
# 2. Первый запуск — программа спросит Client-Id и Api-Key
.\OzonPilot.exe

# 3. Дальше ключи уже сохранены, запуск с параметрами
.\OzonPilot.exe -prodazhi 28 -postavka 25 -clusters "Москва"
```

Либо просто двойной клик по `run.bat` — он делает то же самое без аргументов.

### Из исходников

```bash
go run ./cmd/app -prodazhi 28 -postavka 25
go build -ldflags="-s -w" -o OzonPilot.exe ./cmd/app
```

Требуется Go 1.26 (см. `go.mod`).

### Offline-режим (без сети и без ключей)

```powershell
.\OzonPilot.exe -file doc\example-offline.json -clusters "Москва,Санкт-Петербург"
```

В этом режиме программа не ходит в Ozon, а берёт уже готовые строки из JSON. Формат описан в [data-flow.md](data-flow.md#offline-режим-флаг--file), пример — [example-offline.json](example-offline.json).

## Что и куда пишется

| Что | Где | Когда |
|:---|:---|:---|
| Ключи и настройки | `%APPDATA%\CLIForOZON\config.yaml` (Windows), `~/.config/CLIForOZON/config.yaml` (Linux/macOS) | создаётся при первом запуске, перезаписывается при вводе ключей и смене `-clusters` |
| Excel-отчёт | `<папка exe>\reports\ozon_supply_ГГГГ-ММ-ДД_ЧЧ-ММ-СС.xlsx` | после каждого успешного расчёта |
| Логи | stderr, формат `slog` (`time=... level=INFO msg=...`) | всегда |

## Глоссарий

| Термин | Значение |
|:---|:---|
| **FBO** | Товар на складе Ozon (Fulfillment by Ozon). |
| **FBS** | Товар на складе продавца, отправляется со своего склада. |
| **Кластер** | Группа складов Ozon в регионе (Москва, Санкт-Петербург, Юг…). Ozon считает спрос и хранение в разрезе кластеров. |
| **Артикул / OfferID** | Ваш внутренний идентификатор товара (`offer_id`). |
| **SKU** | Идентификатор товара Ozon. Остатки запрашиваются именно по SKU. |
| **Поставка** | Сколько штук нужно довезти в кластер, чтобы закрыть спрос на `-postavka` дней вперёд (плюс 3 дня страхового запаса). |
| **Размещение** | Платное или бесплатное хранение товара на FBO. |
| **Списано за хранение** | Сколько Ozon уже удержал за хранение за последние 28 дней (то же, что в ЛК). |
| **Прогноз Ozon** | Прогноз стоимости размещения из выгрузки ЛК: «на 28 дней» и «до конца месяца». |
| **Оценка хранения** | Собственный расчёт программы, когда прогноза Ozon нет (файл API). Не равен расчёту Ozon. |
| **Окно продаж** | Период `-prodazhi` дней, за который берётся история отправлений. |

## Частые проблемы

| Симптом в логе | Причина | Что делать |
|:---|:---|:---|
| `Ошибка авторизации Ozon` / 401 / 403 | неверные ключи или нет прав | `-reset-keys`, ввести заново; права «Администратор» или «Аналитика» |
| `Ошибка конфигурации` | `config.yaml` битый или недоступен | удалить файл конфига, запустить заново |
| `Invalid keys! Ozon API denied access` | ключи отклонены при проверке | ввести корректные (до 3 попыток) |
| `критическая ошибка загрузки остатков FBO` | 429/5xx, пачки не доехали после 2 проходов | повторить запуск позже; не гонять параллельно другие интеграции |
| `остатки FBO не получены для N товаров` | часть SKU не пришла из API | повторить запуск; если повторяется — смотреть `-debug` |
| `Не удалось автоматически получить отчет о стоимости размещения` | отчёт API не сформировался (ожидание 5 минут на попытку, до 2 попыток) | это предупреждение: отчёт строится с пустыми денежными колонками и предупреждением в титуле; передать выгрузку ЛК через `-placement-file` или повторить запуск |
| Пустые «Списано за хранение» и прогноз | отчёт о размещении не получен | в титуле будет `ВНИМАНИЕ: данные о размещении Ozon не получены`; `-placement-file` с выгрузкой ЛК |
| `Не удалось создать Excel-отчет` | нет прав на запись рядом с exe | перенести exe в доступную папку |
| `нет данных для экспорта` | в каталоге нет товаров / пустой JSON | проверить кабинет и `-file` |

## Сборка, тесты, проверка

```bash
go build -o OzonPilot.exe ./cmd/app   # сборка
gofmt -l .                           # форматирование
go vet ./...                         # статический анализ
go test ./...                        # все тесты, несколько секунд
go test ./internal/client -run TestFetchAllProductsFailsFastOnStocksError -v
```

Тесты покрывают: повторы и отсутствие повторов на 4xx, троттлинг (в тестах отключён), нормализацию кластеров, разбор отчёта о размещении (CSV, Excel API, выгрузка ЛК), формулу прогноза хранения, расчёт поставок и статусов, оформление Excel (цвета, форматы, колонки).

## Ограничения, о которых стоит знать сразу

- Прогноз хранения в режиме без выгрузки ЛК — **оценка программы**, а не расчёт Ozon; расхождение в 2–4 раза нормально. Детали — в [calculations.md](calculations.md#прогноз-хранения-когда-нет-выгрузки-лк).- Продажи считаются по всем отправлениям, кроме `cancelled`; возвраты и невыкупы отдельно не вычитаются.
- Товары, для которых Ozon не вернул SKU, получают нулевой остаток FBO (подробнее — [known-issues.md](known-issues.md#2-товары-без-sku-выглядят-как-дефицит)).
- Если Ozon не отдал отчёт о размещении за отведённое время (5 минут на попытку, до 2 попыток), в титуле и на листе «Легенда» появляется предупреждение, а денежные колонки остаются пустыми — это не «нулевые списания».
- Все запросы идут строго последовательно ради лимитов Ozon: полный каталог на 800+ SKU грузится несколько минут. Это нормально.
