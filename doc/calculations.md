# Расчёты: поставка, статусы, хранение

Все формулы ниже — из `internal/domain`; их поведение закреплено тестами (`calculator_test.go`, `storage_test.go`).

## Обозначения

| Символ | Что это | Откуда |
|:---|:---|:---|
| `D` | среднесуточные продажи кластера (штук в день) | продажи за окно ÷ `-prodazhi` |
| `S` | целевой запас, дней | флаг `-postavka` |
| `L` | страховой запас, дней | константа `3.0` в `cmd/app/main.go` |
| `stock` | остаток FBO в кластере, штук | `/v1/analytics/stocks` |
| `P` | заказы в кластер за окно, штук | `/v3/posting/fbo/list` + `/v3/posting/fbs/list`, кластер назначения (`cluster_to`) |

`D` — дробное число, поэтому поставка может отличаться на единицу от «продажи за период × дни − остаток».

## Поставка

Считается по каждому выбранному кластеру отдельно:

```text
целевой запас = D × (S + L)
дефицит       = целевой запас − stock
поставка      = 0, если дефицит ≤ 0
              = ceil(дефицит), если дефицит > 0
```

То есть `-postavka 25` означает «закрыть 25 дней спроса плюс 3 дня страховки», итого 28 дней. Итоговая поставка товара — сумма по кластерам.

Примеры (из тестов):

| D | S | stock | Целевой запас | Поставка |
|---:|---:|---:|---:|---:|
| 2,0 | 25 | 0 | 56 | **56** |
| 1,0 | 25 | 10 | 28 | **18** |
| 1,0 | 25 | 50 | 28 | **0** |

Важно: поставка не вычитает остаток FBS. FBS влияет только на статус (см. ниже): программа считает, что довозить на FBO нужно независимо от того, есть ли товар на своём складе.

## Статус и приоритет

Проверки идут сверху вниз, срабатывает первая подходящая:

| Статус | Условие | Приоритет |
|:---|:---|:---:|
| `OUT_OF_STOCK` | во **всех выбранных** кластерах `stock == 0` **и** `FBS == 0` **и** сумма `D` > 0 | 1 |
| `NEEDS_FBO` | хотя бы по одному кластеру поставка > 0 | 2 |
| `NEEDS_FBS` | `FBS == 0` (при отсутствии дефицита FBO) | 3 |
| `OK` | всё остальное | 4 |

Нюансы, которые легко упустить:

- «Все кластеры пусты» — это только **выбранные** кластеры. Товар с остатком в невыбранном кластере может выглядеть как `OUT_OF_STOCK`, если в выбранных пусто и FBS = 0. Остаток по всем складам (`TotalFBOStock`) используется только для денежных колонок.
- Если есть товар на FBS, статус никогда не будет `OUT_OF_STOCK` — максимум `NEEDS_FBO`.
- `NEEDS_FBO` важнее `NEEDS_FBS`: если дефицит есть и FBS пуст, статус будет `NEEDS_FBO`.
- Порог спроса — среднесуточные продажи по выбранным кластерам. Товар без продаж не станет `OUT_OF_STOCK`, даже если всё пусто.

## Сортировка строк

1. приоритет по возрастанию (1 → 4);
2. суммарная поставка по убыванию;
3. продажи по убыванию (используются среднесуточные, не период);
4. `OfferID` по возрастанию — чтобы порядок был стабильным.

## Прогноз хранения, когда нет выгрузки ЛК

Функция `StorageForecast`. Входные данные: текущий остаток по всем складам, продажи за окно, прошлое списание, окно, горизонт (30 дней), дата окончания бесплатного размещения, «сейчас».

```text
если stock ≤ 0 или pastCost ≤ 0:                  → 0
средний остаток за прошлый период = stock + P / 2
тариф за экземпляр в день        = pastCost / (окно × средний остаток)
свободных дней                   = ceil((freeUntil − now) / 24ч), не меньше 0
дневные продажи                  = P / окно

экземпляро-дни = 0
для day = 0 … 29:
    если day < свободных дней: пропустить
    остаток_в_день = stock − дневные_продажи × day
    если остаток_в_день ≤ 0: прервать
    экземпляро-дни += остаток_в_день

прогноз = round(тариф × экземпляро-дни, 2)
```

Смысл: тариф неизвестен, поэтому он восстанавливается из прошлого списания и приблизительного среднего остатка. Дальше прогноз идёт по дням, остаток тает на дневные продажи, а дни бесплатного периода не тарифицируются.

Примеры (все проверены тестами):

| stock | P | pastCost | окно | freeUntil | Результат | Почему |
|---:|---:|---:|---:|:---:|---:|:---|
| 10 | 0 | 280 | 28 | — | **300,00** | тариф 1 ₽/шт/день × 10 шт × 30 дн |
| 10 | 280 | 1960 | 28 | — | **4,67** | тариф 0,467 ₽; товар уходит за 1 день, 10 экземпляро-дней |
| 30 | 0 | 840 | 28 | +10 дн | **600,00** | 20 платных дней × 30 шт × 1 ₽ |
| 30 | 0 | 840 | 28 | +60 дн | **0** | бесплатный период закрывает горизонт |
| 10 | 0 | 280 | 28 | −5 дн | **300,00** | бесплатный период уже закончился |
| 10 | 0 | 280 | 28 | через 30 минут | **290,00** | `ceil` даёт 1 свободный день, тарифицируются 29 |

Когда прогноз равен нулю: остатка на FBO нет; прошлых списаний не было (тариф неизвестен); размещение бесплатное на весь горизонт; отчёт о размещении не загружен вообще.

## Прогноз Ozon из выгрузки ЛК

Если в данных есть колонки прогноза (выгрузка «Стоимость размещения по товарам»), программа показывает их как есть и **не** подменяет своей оценкой: `HasOzonForecast = true` у любой строки переключает отчёт на две колонки — «на 28 дней» и «до конца месяца».

Смешать режимы нельзя: колонки общие для всего листа, поэтому режим выбирается по факту наличия прогноза, а не по каждой строке.

## Почему оценка расходится с Ozon

Это разные модели, а не ошибка округления:

- **Ozon** считает: объём товара в литрах × тариф ₽/л/день × дни платного размещения. Тариф для обычных товаров — 2,5 ₽/л/день (с 12.09.2026), бесплатное размещение — 120/150/365 дней с даты приёмки в зависимости от категории.
- **Программа** считает: восстановленный из прошлого списания тариф ₽/шт/день × экземпляро-дни, с приблизительным средним остатком `stock + P/2`.

Для точного повторения расчёта Ozon нужны объём каждой единицы и даты приёмки по каждой поставке на каждый склад — в API этих данных нет. Отсюда расхождение в 2–4 раза. Цифры Ozon доступны только в выгрузке ЛК.

## Числа в титуле отчёта

| Элемент титула | Как считается |
|:---|:---|
| `позиций` | число строк отчёта |
| `платное хранение` | строки, у которых `PlacementInfo` классифицируется как «Платно» |
| `списано за хранение` | сумма `StorageCost` по всем строкам |
| `из них без остатка на FBO` | та же сумма, но только по строкам с `TotalFBOStock == 0` |
| `оценка хранения за 30 дн.` | сумма `StorageForecast` (режим без прогноза Ozon) |
| `прогноз Ozon: … на 28 дн., … до конца месяца` | суммы `OzonStorageForecast28` / `OzonStorageForecastMonth` |
| `закончилось` | число строк со статусом `OUT_OF_STOCK` |

Суммы округляются до целых рублей и разделяются пробелами по разрядам.

## Округления и форматы

- поставка — целое вверх (`ceil`);
- прогноз хранения — до копеек (2 знака), в титуле — до рублей;
- продажи в Excel — целые (`#,##0`), остатки и поставки — целые числа без дробной части;
- деньги в Excel — `#,##0.00`.

## Границы применимости

- Расчёт линейный: спрос берётся средним за окно, сезонность и тренды не моделируются. Всплеск продаж за окно завышает поставку, затишье — занижает.
- Заказы, для которых Ozon не вернул кластер назначения и склад не опознан, не участвуют в кластерном спросе: они видны только в общей сумме, а в лог уходит предупреждение.
- Страховой запас зашит константой; поменять его можно только в коде.
- Прогноз хранения — оценка, а не обязательство Ozon. Для денег в отчёте используйте выгрузку ЛК.
